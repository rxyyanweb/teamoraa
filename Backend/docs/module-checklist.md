## Business rules preserved for next phases

**Phase 2:** Backend stamps attendance time; one check-in per person/day, duplicates 409. Default start 09:00, grace 15 minutes, half day under 5 hours, Saturday/Sunday weekends. Apply settings to new records only. Handle present, late, half_day, absent, on_leave and missing_checkout. Corrections need reason and HR decision. Leave counts working days, excluding holidays/weekends; annual 14, sick 8, casual 10, unpaid unlimited; overlap/insufficient balance returns 422. HR cannot approve their own requests; the PDF does not resolve HR leave-approval escalation, so that policy must be made explicit before implementation.

**Phase 3:** Gross = 1.5 × basic (40% HRA + 10% medical). Per-day = gross / working days. Deduct absent/unpaid + 0.5 × half-days; prorate joiners/leavers. Implement the PDF's illustrative annualized tax slabs (0 through 600k; 5% next band to 1.2M; 30k + 15% to 2.4M; 210k + 25% to 3.6M; 510k + 35% above). This is a hackathon rule, not a claim of current legal tax compliance. Finalization is Admin-only and locks all future changes. All sums/rounding live on the backend. Implement PDF metric formulas: headcount/attrition, attendance, late percentage, absenteeism, leave utilization, gross/net payroll costs and average salary, filterable by date and department.

**Phase 4:** Gemini tool-calling services for `get_headcount`, `get_attendance_summary`, `get_late_comers`, `get_leave_summary`, `get_my_leave_balance`, `get_payroll_summary`, `search_employees`. Tools reuse authorized backend services. No direct database access by the model and no autonomous writes. Dashboard summary uses only current KPI JSON, 3–5 bullets. Smart leave validates JSON, retries once, then falls back to a normal form; user confirms before save. Policy answers only from configured rules. Per-user ~20/hour limit, 15-second timeout, `ai_logs`, AI-generated labels, Roman Urdu support. Announcements, own notifications and complete sanitized audit snapshots.

**Phase 5:** Browser face detection requires exactly one face. Backend Haversine distance validates office radius, rejects poor GPS accuracy >100m, stores results instead of photos, provides HR correction fallback and explains capture. Optional face descriptors/liveness require explicit design and privacy review. Add PWA/dark mode, attrition risk indicators, absence anomalies and configurable late penalty (3 lates = 0.5 day). Deploy all three applications, test production cookies/CORS/HTTPS and build the 5-minute judge demo. Native mobile app remains optional per PDF; browser camera attendance stays on this roadmap as requested by the user.

## Current gate

Only Phase 1 is being delivered. API/browser tests use isolated MongoDB. Atlas validation must succeed separately before claiming Phase 1 verified and proceeding to Phase 2. Full metrics, AI, attendance or leave are never silently marked complete.
