# Teamora — AI-Powered Human Capital Management (Backend API)

For the current **Deno Deploy** platform, follow [the verified deployment guide](docs/deno-deploy.md). The production entrypoint is **`dist/server.js`**, generated by `npm run build`; `deno.json` contains the install, build and dynamic runtime settings. `/health` is liveness and `/api/health` checks MongoDB readiness.

Teamora is an enterprise-grade Human Capital Management (HCM) platform backend built with Express 5, TypeScript, MongoDB Atlas (Mongoose), Google Gemini 2.5 AI SDK, and PDFKit.

This service powers all business logic, role-based access control (Admin, HR, Employee), attendance calculation, payroll processing, PDF payslip generation, and AI assistant tool calls.

---

## 🌟 Features & Architecture

- **Strict TypeScript & ESM**: Modern ES modules compiled with `tsc` to clean production JavaScript.
- **Role-Based Access Control (RBAC)**: Secure multi-tier permissions for `admin`, `hr`, and `employee`.
- **Dual-Session Cookies**: Partitioned HttpOnly cookies (`teamora_admin_session` and `teamora_staff_session`) preventing session hijacking across admin and staff interfaces.
- **Attendance & Leave Logic**: Comprehensive shift management, check-in/out anomaly detection, dynamic leave balance tracking, and carry-forward quota calculations.
- **Payroll Lite Engine**: Attendance-based proration, Pakistani tax bracket calculations, draft previewing, admin-only payroll finalization, and downloadable PDF payslips generated via PDFKit.
- **Gemini AI Integration**: Real Gemini 2.5 model invocation with tool execution for policy lookups, smart leave submission, and Roman Urdu language comprehension.
- **Security & Auditing**: Tamper-evident audit logging for sensitive actions, Helmet security headers, rate limiting, and CORS origin validation.
- **Health Checks**: Zero-downtime health endpoints available at `/health` and `/api/health`.

## 🛠️ Getting Started Locally

### Prerequisites
- **Node.js**: `v20.x` or `v22.x`
- **npm**: `v10.x` or higher
- **MongoDB**: Local MongoDB instance (`mongodb://127.0.0.1:27017/teamora`) or MongoDB Atlas cluster URI.

### Installation
```bash
# Clone the repository
git clone <repo-url> teamora-backend
cd teamora-backend

# Clean install dependencies
npm ci
```

### Environment Configuration
Create a `.env` file from the provided example:
```bash
cp .env.example .env
```
Fill in your configuration:
```env
NODE_ENV=development
PORT=5000
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/teamora?retryWrites=true&w=majority
JWT_SECRET=your_super_secret_jwt_key_at_least_32_characters
ADMIN_EMAIL=admin@teamora.com
ADMIN_PASSWORD=YourSecurePassword123!
FRONTEND_URL=http://localhost:3000
ADMIN_PANEL_URL=http://localhost:3000
COOKIE_SECURE=false
COOKIE_SAME_SITE=lax
GEMINI_API_KEY=your_google_gemini_api_key
```

### Running the Server
```bash
# Start in development mode with hot-reloading (tsx)
npm run dev

# Or build and run production server
npm run build
npm run start
```
The server will start listening at [http://localhost:5000](http://localhost:5000).

### Available Scripts
- `npm run dev`: Runs development server via `tsx watch src/server.ts`.
- `npm run build`: Compiles TypeScript to JavaScript in `dist/` using `tsconfig.build.json`.
- `npm run start`: Launches compiled production server from `dist/server.js`.
- `npm run typecheck`: Validates zero TypeScript errors (`tsc --noEmit`).
- `npm run test`: Executes unit and integration tests using Vitest (77 tests).
- `npm run check:db`: Validates connection and indexes on the configured MongoDB database.

## 🚀 Deploying to Render / Railway

### Deploying to Render
1. Push this repository to GitHub.
2. In the [Render Dashboard](https://dashboard.render.com), click **New + > Web Service**.
3. Connect your repository.
4. Set the following settings:
   - **Environment**: `Node`
   - **Build Command**: `npm ci && npm run build`
   - **Start Command**: `npm run start`
   - **Health Check Path**: `/health`
5. Under **Environment Variables**, provide:
   - `NODE_ENV`: `production`
   - `PORT`: `5000` (or leave default Render auto-assigned port)
   - `MONGODB_URI`: Your MongoDB Atlas connection string
   - `JWT_SECRET`: A secure 64+ character random string
   - `FRONTEND_URL`: Your deployed frontend URL (e.g., `https://teamora.vercel.app`)
   - `ADMIN_PANEL_URL`: Same as `FRONTEND_URL` in the unified architecture
   - `COOKIE_SECURE`: `true`
   - `COOKIE_SAME_SITE`: `none` (required for cross-origin cookies between Vercel and Render)
   - `TRUST_PROXY`: `1`
   - `GEMINI_API_KEY`: Your Google Gemini API Key
6. Click **Deploy Web Service**.

Alternatively, you can deploy using Render Blueprints using the included `render.yaml` file.

### Deploying to Railway
1. Push this repository to GitHub.
2. In [Railway](https://railway.app), create a new project and select **Deploy from GitHub repo**.
3. Railway will automatically detect Node.js and use the included `railway.json`.
4. Add the required environment variables in the **Variables** tab.
5. Railway will automatically provision, build, and deploy the service.
